# Known limitations

The original SQLite workspace limitations below remain applicable to that workspace. The new authenticated `/practice` implementation has a PostgreSQL backend and initial sharing workflows; see [PRACTICE_SETUP.md](PRACTICE_SETUP.md) for its separate scope. Object storage, distributed jobs, EHR interoperability, protected audit export, key rotation, institution-specific clinical approval and disaster recovery remain outstanding.

1. **Live note generation needs provider credentials.** Native Claude and OpenAI-compatible note adapters exist, but mocked tests do not establish real connectivity or model quality. Audio can use the installed local Whisper engine without an API key, or a separate compatible audio API. Local mode supports the nine documented languages in clips up to three minutes, one transcription at a time, with contextual AI speaker inference at note generation. Physical microphone permission and recording behavior still require a manual device check.
2. Offline generation is a keyword baseline, not AI. It preserves contradictory/obsolete statements and can miscategorize language. The evaluation deliberately exposes these errors.
3. Exact quotes validate source existence, not semantic support. “Source linked · verify meaning” is intentionally qualified. The system cannot prove that a paraphrase is accurate.
4. Personal note generation uses transcript evidence; Trust audits additionally use explicitly recorded patient context. Shared audits use selected authorized sources and recorded medication provenance. Synthetic safety rules cover only penicillin/amoxicillin and same-drug aspirin/ibuprofen examples. There is no comprehensive interaction checking, diagnostic advice, prescribing, clinically validated multilingual accuracy, or acoustic diarization.
5. Extraction evaluation uses eight development-visible synthetic examples; Trust adds 24 local fixtures and eight provider-backed fixed drafts. The separate 12-case fictional follow-up suite produced a 47/47 exact segment/category match after local rules were tuned against those same authored cases; it is not held-out validation and does not measure semantic or clinical accuracy. All labels are author-written. There is no independent clinical review, audio quality scoring, or statistical confidence interval. These suites are engineering checks, not evidence of clinical safety.
6. SQLite and application-level audit history require a persistent single Node server. Sites/Cloudflare deployment is not implemented. Docker is unverified unless the quality report states otherwise.
7. Notes can be edited statement by statement, but adding completely new SOAP sections is not exposed in the editor. Correct/add source content and regenerate if needed. Version history is retained and available through an authenticated endpoint, not a full visual diff UI.
8. Recordings use post-recording uploads, with a 20 MB server limit. No streaming, audio recovery after reload, durable audio storage or incremental transcript. Unsaved transcript changes show a warning when leaving the page; no cross-session local draft autosave.
9. PDF exports now embed licensed Noto fonts for the supported Latin, CJK, Korean and Tamil text, with paragraph wrapping and pagination. These layouts were rendered and inspected; uncommon glyphs and languages beyond the documented set still need review.
10. No certified e-signature, enterprise accounts, real patient data workflow, regulatory claims, clinical validation or institutional deployment readiness.
11. Optional Stage B features (diarization, verified medication risk database, advanced templates, dark mode, shortcuts) are intentionally deferred. Basic analytics are calculated from actual stored data.
12. No independent accessibility audit or exhaustive browser/device testing. See actual verification in the quality report.

## Trust Engine-specific limits

Semantic checks can be wrong, incomplete, or duplicated. Exact source quotes do not prove semantic support. Fixed English negation, date and medication rules are deliberately narrow; multilingual source handling does not mean multilingual audit validation. Oversized claims remain visible as not checked. Provider requests may fail, refuse, truncate, or omit results; these conditions remain reviewable, without automatic retries.

Findings prompt human review. A reviewer rationale records a decision; it does not establish that the decision is clinically correct. “Not established” means absent from the audited material, not clinically absent. No match in synthetic allergy rules must never be interpreted as safe medication use or no known allergies.

Patient summaries are clinician-reviewed English derivative drafts, not patient messaging or remote access to medical records. Source changes and amendments block approval; edits invalidate prior findings. Summary translation is not implemented. Provider-backed generation requires consent and may incur provider charges; no cost-per-consultation estimate has been measured.

All software checks use synthetic data. There is no clinical validation, independent accessibility certification, institutional deployment approval, or blanket encryption/compliance guarantee. Actual testing and the observed semantic duplicate-target failure are recorded in TRUST_IMPLEMENTATION.md and EVALUATION.md.
